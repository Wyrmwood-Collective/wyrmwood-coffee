## Development Setup

Install `uv` and clone the repository:

```shell
winget -e --id=astral-sh.uv
git clone git@github.com:bverble-catalyte/wyrmwood-coffee.git
```

Create a local env file from the committed template and fill in real values
(never commit `.env.local`). If `.env` files are new to you, read
[docs/configuration.md](docs/configuration.md) first — it explains what each
file is for and which one is safe to put in git.

```shell
copy .env.example .env.local
```

Replace `USER:PASSWORD` with your local Postgres username and password. Replace
`JWT_SECRET_KEY` with a random string of at least 32 characters.

Run the development server:

```shell
uv run dev
```

If a required secret is missing or still a placeholder, the process exits
immediately with the variable name. That is a missing-config error, not a
mystery crash.

Run test suite:

```shell
uv run pytest
```

## Database Migrations

This project uses [Alembic](https://alembic.sqlalchemy.org/) to manage database schema changes. Alembic reads the connection URL from `DEV_DATABASE_URL` in your `.env` file.

Apply all pending migrations:

```shell
uv run alembic upgrade head
```

After changing a SQLAlchemy model, generate a new migration and review the autogenerated file before committing it:

```shell
uv run alembic revision --autogenerate -m "short description of the change"
```

Other useful commands:

```shell
uv run alembic downgrade -1   # roll back the most recent migration
uv run alembic history        # list migrations
uv run alembic current        # show the currently applied revision
uv run alembic check          # verify that models match schema
```

## Hosted PostgreSQL Database

The development database is hosted on Neon PostgreSQL.

- Provider: Neon
- Project: Wyrmwood-Collective Coffee API
- Branch: production
- Database: wyrmwood_collective
- Port: 5432
- SSL: Required
- Environment variable: DEV_DATABASE_URL

Connection credentials are stored locally in the `.env` file and must not be committed to source control.

Team members should retrieve the current database credentials through the approved team credential-sharing method rather than placing passwords in GitHub, Jira, or documentation.
